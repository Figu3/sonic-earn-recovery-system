# V2.1 Design Doc — StreamRecoveryClaim Signature Remediation

**Date**: 2026-04-08
**Owner**: figue
**Status**: pre-implementation — gates Phase G fork matrix

---

## F1. Bug statement (one sentence)

The V2 contract's `signWaiver` ABI (`uint8 v, bytes32 r, bytes32 s`) forces a 65-byte signature, which is mathematically insufficient for any multi-sig Safe with threshold ≥ 2 and routes EIP-7702 delegated EOAs down a broken ERC-1271 code-has-code path, leaving ≥ 24 Safes and ≥ 13 7702-delegated EOAs unable to sign the liability waiver that gates every claim.

## F2. Root cause (exact lines of code)

`src/StreamRecoveryClaim.sol`:

- **L267** — `function signWaiver(uint8 v, bytes32 r, bytes32 s)`. The parameter shape hard-caps the payload to `1 + 32 + 32 = 65 bytes`. Gnosis Safe's `isValidSignature(bytes32 digest, bytes signature)` consumes an `N × 65` multi-sig bundle for threshold `N`; a 2-of-N Safe needs ≥ 130 bytes, a 3-of-N needs ≥ 195 bytes, a 4-of-N needs ≥ 260 bytes. The ABI physically cannot carry them. This is Bug #1 of Phase A and the direct cause of Phase A tests `test_2of_N_fails`, `test_3of_N_fails`, `test_4of_N_fails`.
- **L280** — `SignatureChecker.isValidSignatureNow(msg.sender, digest, abi.encodePacked(r, s, v))`. On an EIP-7702-delegated EOA, `msg.sender.code.length > 0` (the 23-byte `0xef0100…` delegation designator), so OpenZeppelin's `SignatureChecker` routes to the ERC-1271 `isValidSignature` branch and calls into the delegation target, which is not an ERC-1271 wallet and reverts (or returns non-magic bytes). The underlying EOA's ECDSA key is never consulted even though the 7702 EOA can sign ECDSA. This is Bug #5 of Phase A, covered by `test/Fork7702Waiver.t.sol`.
- **L253–260** — `migrateWaiverFromV1` reads `v1.hasSignedWaiver(msg.sender)`. V1 was deployed with the same L267-style ABI, so any user who could not sign V1 cannot migrate into V2 either. This is a dependent failure, not a root cause: fixing L267 fixes the signing path, and users who had no V1 waiver simply sign V2.1 directly via the new ABI.

## F3. Preconditions — every user category that MUST work

A fix is only real if **every** category below completes `signWaiver` and then `claim{Usdc,Weth,Both}` end-to-end on a Sonic fork:

1. EOA with a pre-existing V1 waiver (migrates via `migrateWaiverFromV1`)
2. EOA with no V1 waiver (signs V2.1 directly)
3. 1-of-1 Safe (threshold 1)
4. 2-of-N Safe (threshold 2) — real target `0x4d62…ff1d` (Silo recipient Safe, 24 of these stuck)
5. 3-of-N Safe (threshold 3) — real target `0x7D1C…6676`
6. 4-of-N Safe (threshold 4) — real target `0x6a15…6567`
7. Non-Safe ERC-1271 wallet (Argent / Coinbase Smart Wallet / delegated wallets) — if any appear in the R0v2 address set
8. EIP-7702-delegated EOA with delegation code present — real targets from `7702-scan.json`
9. WQ-ETH pending user (new leaf in R0v2 tree) → claim amount matches rate-derived payout from `wq-payouts.json`
10. WQ-USD pending user → same
11. Shadow CL / 9mm LP holder → receives pro-rata share from sub-distribution
12. Address that already claimed V1 Round 0 → correctly EXCLUDED (reverts `AlreadyClaimed` or has no leaf)

## F4. Fix (one sentence)

Replace V2's `signWaiver(uint8,bytes32,bytes32)` ABI with `signWaiver(bytes calldata signature)` that accepts a variable-length payload, and resolve the signature inside the function by attempting ECDSA recovery first (handles EOAs including 7702-delegated EOAs, regardless of whether `code.length > 0`) and falling back to ERC-1271 via `SignatureChecker.isValidERC1271SignatureNow` only if the payload length ≠ 65 or ECDSA recovery does not return `msg.sender`.

## F5. Why the fix addresses each precondition

- **(1) EOA + V1 waiver**: `migrateWaiverFromV1` is unchanged and still reads `v1.hasSignedWaiver(msg.sender)`. Any EOA that successfully signed V1 continues to migrate via the unchanged path. Satisfied by L253–260 (unchanged).
- **(2) EOA without V1 waiver**: submits a 65-byte `(r,s,v)` blob via the new `bytes` parameter; `ECDSA.tryRecover` returns `msg.sender`; the ERC-1271 branch is not entered.
- **(3–6) Safes, any threshold**: submits the full `N × 65`-byte Safe multi-sig bundle (or longer, if Safe prepends signature data). ECDSA recovery on a payload of length ≠ 65 returns `(address(0), _)`, triggering the ERC-1271 fallback. `SignatureChecker.isValidERC1271SignatureNow(msg.sender, digest, signature)` calls Safe's `isValidSignature(digest, signature)`, which parses the bundle and validates each owner signature. Works for threshold 1, 2, 3, 4, N — nothing in the logic depends on threshold.
- **(7) Non-Safe ERC-1271 wallet**: identical path to (3–6). Any compliant ERC-1271 wallet that returns the `0x1626ba7e` magic value on `isValidSignature` passes.
- **(8) EIP-7702 EOA**: ECDSA recovery is attempted FIRST, **before** the `code.length` check. A 7702 EOA's private key is still valid and signs the EIP-712 digest; `tryRecover` returns the EOA address; match succeeds; the broken ERC-1271 branch is never reached. This is the whole reason for trying ECDSA first.
- **(9–10) WQ users**: not a contract fix — these are leaves in the V2.1 merkle tree. Phase E added them; Phase G `test_wq_{eth,usd}_*` asserts claim amounts match `wq-payouts.json`.
- **(11) Shadow CL / 9mm LP**: not a contract fix — sub-distribution was baked into the V2.1 tree in Phase E. Phase G asserts holders can claim at the pro-rata amount.
- **(12) Already-claimed exclusion**: dropping these addresses from the V2.1 tree was done in Phase E (Step 10 of rebuild). Phase G asserts their `claim*` calls revert with `InvalidProof` (leaf absent from the new root) and the V1 claim remains unaffected.

## F6. Test plan

Every test below lives in `test/ForkV21Waiver.t.sol` (new file), uses a Sonic fork at a recent block, deploys a fresh `StreamRecoveryClaimV21` in-test, creates Round 0v2 with the V2.1 roots from `merkle-round0v2-v2.1-{usdc,weth}.json`, and exercises the full user-facing flow (`signWaiver` → `claim*`).

| ID | Test | Real target | Asserts |
|---|---|---|---|
| G1 | `test_eoa_v1_migrate_then_claim` | any claimed EOA from `round0-claimed.json` | `migrateWaiverFromV1` ok; claim reverts `AlreadyClaimed` |
| G2 | `test_eoa_fresh_sign_then_claim` | any unclaimed EOA with a new-tree leaf | `signWaiver(65-byte)` ok; claim balance delta == leaf amount |
| G3 | `test_safe_1of1_sign_then_claim` | any 1-of-1 Safe in the tree | balance delta == leaf |
| G4 | `test_safe_2ofN_sign_then_claim` | `0x4d62…ff1d` (Silo recipient) | threshold check ok; balance delta == leaf |
| G5 | `test_safe_3ofN_sign_then_claim` | `0x7D1C…6676` | balance delta == leaf |
| G6 | `test_safe_4ofN_sign_then_claim` | `0x6a15…6567` | balance delta == leaf |
| G7 | `test_7702_eoa_sign_then_claim` | any 7702 address from `7702-scan.json` with a new-tree leaf | ECDSA path wins over ERC-1271; balance delta == leaf |
| G8 | `test_wq_eth_user_claim` | any addr from `withdraw-queue-resolved.json#eth.perUser` | claim amount == `wq-payouts.json#wq_eth_payouts[addr]` ± 1 wei |
| G9 | `test_wq_usd_user_claim` | any addr from `withdraw-queue-resolved.json#usd.perUser` | claim amount == `wq-payouts.json#wq_usd_payouts[addr]` ± 1 wei |
| G10 | `test_9mm_lp_holder_claim` | any addr from `9mm-resolved.json#perUser` | claim amount == pro-rata share |
| G11 | `test_claimed_v1_cannot_reclaim_v21` | any addr from `round0-claimed.json` | claim reverts `InvalidProof` (leaf absent from new root) |
| G12 | `test_non_safe_1271_wallet_claim` | any ERC-1271 wallet in the tree, if present; otherwise `vm.skip(true)` | balance delta == leaf |

**Hard gate**: zero failures. If any test fails, V2.1 does not deploy. Phase H (`/solidity-auditor deep`) runs on the diff after G passes; if it flags a category not covered here, we return to G and add it.

**Out of scope for V2.1**: pausing, rescueToken, EIP-712 domain bump (the domain version string changes from `"2"` to `"2.1"` to invalidate any stale V2 signatures), createRound/deactivateRound semantics. Those are unchanged from V2. Only the `signWaiver` function and its tests are touched.
